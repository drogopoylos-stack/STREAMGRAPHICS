# Create-tournament wizard

Status: spec, ready to build · Owner: UI/style lead · Engine: `server/formats/index.js` (`FORMATS`, `generateTournament`, `scheduleMatches`, `standings`) · Mockups: `jobs/proto/wizard.html` (`?step=1…8`, `2b`), screenshots in `jobs/proto/shots/wizard/`, mockup data generated by the real engine (`jobs/proto/wizard-data.mjs`).

The user's request: *"create a tournament WITHOUT a connection with AI agents"*. Everything an agent did for SUPERCUP 2026 (teams, bracket, matches, schedule, design) becomes a guided form in the app.

---

## 0. Decisions at a glance

| # | Decision |
|---|---|
| W1 | **Full-page wizard** at `#/new-tournament`, inside the control-panel shell. It has a step rail on the left, a live summary on the right and Back/Next in the footer. Drawers are too narrow for teams, bracket and calendar. |
| W2 | **Seven steps:** Name & look → Teams → Format → Seeding → Schedule → Google Sheet (optional) → Review. A success screen with next steps follows. |
| W3 | **Nothing is written until Create.** The draft lives in `localStorage` (`hll-tournament-wizard-draft-v1`) and survives reloads. Closing keeps it; **Start over** clears it. |
| W4 | Previews (match counts, play days, first round, calendar, bracket) come from the **real engine**, through a stateless endpoint `POST /api/formats/preview`. |
| W5 | **One atomic create call:** `POST /api/tournaments/wizard`. It validates everything, then creates the tournament, teams, copied players, matches, `settings.brackets`, the format-screen text, the design, and optionally the Sheet link (sync **off**). |
| W6 | The new tournament is **not activated** automatically, so the live broadcast is never interrupted. The success screen offers **Switch to it**. |
| W7 | The wizard input is saved on the tournament (`settings.wizard`), so **Regenerate bracket…** can reopen the wizard later, as long as no match has started. |
| W8 | **Weekday numbering differs:** `broadcastDays` uses 1 = Mon … 7 = Sun; `scheduleMatches` uses 0 = Sun … 6 = Sat. Convert in exactly one helper (§6.3). |

## 1. Entry points

1. **Tournaments drawer** (`tournaments.js openManager`): the footer primary button becomes **Create tournament** (opens the wizard). The old quick dialog stays as a secondary button **Add empty tournament**.
2. **Active-tournament picker** in the top bar: last option **＋ Create tournament…**.
3. **Empty state**: when a tournament has no teams and no matches, Teams, Matches and Live show the card **"Start with the tournament wizard — teams, bracket and schedule in a few minutes." [Create tournament]**.
4. If a wizard draft exists, the entry points show **Continue tournament draft (SUPERCUP Winter 2026)** instead, with a small **Start over** link.

Route: `#/new-tournament` (a section like the others, but hidden from the nav list). Leaving with unsaved changes needs no confirmation (the draft is kept). The section's `isDirty()` returns false.

## 3. Steps

### Step 1 · Name & look (`shots/wizard/step-1.png`)

| Field | Control | Rules / copy |
|---|---|---|
| Tournament name * | text, 100 | required. Error: **"Enter a tournament name."** Duplicate of an existing tournament name: warning (not blocking), **"Another tournament is called SUPERCUP 2026. Use a different name to tell them apart."** Hint: "Shown as {tournament} on graphics." |
| Short name | text, 8, upper | default: initials of the name words (≤ 8), else first 8 letters. Hint: "Up to 8 characters." |
| Season | text, 80 | optional |

| Graphics design | select from `designLibrary.presets` | default: library default. Hint: "A preset from the Graphics designer library." |

### Step 2 · Teams (`step-2.png`, `step-2b.png`)

Three tabs over one shared **team list**:

1. **Add one by one**: name field + tag field + **Add team**. Enter adds the team and keeps focus in the name field. The tag fills itself from the name (initials, or the first 3 letters for one word; uppercase; 2–5 letters/digits) until the user edits it.
2. **Paste a list**: a textarea. One team per line, optional tag after a comma or a tab. The live preview line reads: **"6 teams found · 2 tags made automatically (TPI, WOL) · 1 already in your list: Alpha Impact (skipped)"**. Then **Add 5 teams**.
3. **Copy from a tournament**: a dialog with a tournament select, a checkbox list of its teams (logo, name, player count), and a toggle **"Copy their players and rosters too"** (default on). Footnote: **"Copies are independent: changing a team here does not change it in SUPERCUP 2026. Logos and photos are copied."** Button: **Copy 3 teams**.

List row: `#` · logo slot (drop an image, or "+ logo") · name (+ "copied from X with 5 players") · tag chip · colour swatch (click → colour picker; default from a fixed 12-colour palette in list order) · ✕ remove. Rows can be edited in place (click name or tag).

**＋ Add a place to be decided**: adds a TBD row (no name, label "To be decided"). It becomes a `null` seed in the engine (label `Seed N`, a real slot, not a bye). Use it for "2 qualifiers to be decided" as in SUPERCUP.

Validation (blocking unless noted):

| Case | Message |
|---|---|
| fewer than 2 teams (TBD places count) | **"Add at least 2 teams."** |
| empty name | **"Enter a team name."** |
| same name twice (case-insensitive, trimmed) | **"{name} is already in the list."** |
| same tag twice | **"Tag {TAG} is already used by another team. Tags must be unique."** |
| tag not 2–5 letters/digits | **"Use 2 to 5 letters or digits for the tag."** |
| more than 64 teams | **"A tournament can have up to 64 teams."** |
| team without logo | none, only counted on Review ("5 without a logo yet") |

### Step 3 · Format (`step-3.png`)

Four cards in a 2×2 grid (radiogroup), each with a small diagram, the name, one line, and a live count line from `/api/formats/preview` with the current teams and options:

| Card (FORMATS id) | Line | Count line example (8 teams) | Disabled when |
|---|---|---|---|
| **Single elimination** (`single-elimination`, 2–64) | "Lose once and you are out. Fast, dramatic, ideal for cups." | 8 teams → 8 matches (with 3rd place) | outside 2–64 |
| **Double elimination** (`double-elimination`, 4–32) | "Upper and lower bracket: a team is out after two losses." | 8 teams → 14 matches | outside 4–32 |
| **GSL groups** (`gsl`, 4–32, ×4) | "Groups of four. Two wins qualify, two losses eliminate. Top 2 advance." | 8 teams → 10 matches · 2 groups of 4 | not a multiple of 4 |
| **Round robin** (`round-robin`, 3–20) | "Everyone plays everyone. A league table decides the ranking." | 8 teams → 28 matches | outside 3–20 |

A disabled card stays visible and says why in amber, for example **"GSL needs a multiple of 4 teams. You have 6: add 2 or remove 2."** or **"Round robin allows up to 20 teams. You have 24."**

Options panel for the selected format (from `FORMATS[].options`):

| Option | Control | Formats | Copy |
|---|---|---|---|
| `bestOf` | segmented 1 · 3 · 5 | all | "Best of" |
| `finalBestOf` | segmented Same · BO3 · BO5 (· BO7 for DE/SE) | all except round robin | "Final". Same = `null` |
| `thirdPlace` | toggle | single elimination (≥ 4 teams) | "Third place match" |
| `grandFinalReset` | toggle | double elimination | "Grand final reset". Hint: **"If the lower-bracket team wins the grand final, a second final decides the title."** |
| `double` | toggle | round robin | "Home and away (everyone plays twice)" |
| `roundBestOf` | **Advanced ▸** per-round list (round name → 1/3/5) | all | "Best of per round" |

Byes: for single/double elimination with a team count that is not a power of two, show **"With 6 teams, seeds 1 and 2 get a bye in the first round."** (the number of byes = next power of 2 − teams, given to the top seeds).

Engine warnings (`result.warnings`) are shown in the options panel as amber notes. Rewrite the two known warnings in plain words:
* no reset: **"Without a reset, the grand final winner is champion, even if the upper-bracket team then has only one loss."**
* reset: **"The second final (GF2) is played only if the lower-bracket team wins the first. It is scheduled as a reserve slot."**

### Step 4 · Seeding (`step-4.png`)

* An ordered list (seed 1 at the top) with drag handles, logo, name, and a hint column (e.g. "2nd in SUPERCUP 2026").
* Buttons: **⇅ Random draw** (undoable with Ctrl+Z or the toast **Undo**), **Seed by {tournament} result ▾**, **Reverse**.
* **Seed by result** orders the teams by final position in a chosen earlier tournament. Teams are matched by `sourceTeamId` first, then by tag, then by name. For knockout brackets use the elimination round (champion, finalist, semifinalists by seed…). For round robin use `standings()`. Teams with no result go last, in their current order. Toast: **"6 teams seeded by SUPERCUP 2026. 2 had no result there and were placed last."**
* The right column shows the **first round** live from the engine: SE/DE pairings (`QF1: 1 Team Phantasma vs 8 Olympus Five`), GSL groups (A: 1, 4, 5, 8 snake), round robin (Round 1 pairs). Text: **"Seed 1 is your strongest team. Seeds 1 and 2 can only meet in the final."** (GSL: "Seeds are spread over the groups in a snake: 1 and 2 are in different groups.")
* Keyboard: focus a row, **Alt+↑ / Alt+↓** moves it; the new seed is announced.

### Step 5 · Schedule (`step-5.png`)

| Field | Control | Rules |
|---|---|---|
| First match day | date | required unless TBD. Today or later; a past date is a warning only |
| Broadcast days | 7 chips Mon…Sun | at least 1. Default: the current tournament's broadcast days, else Fri/Sat/Sun |
| Start times | chips + **＋ time** (HH:mm) | at least 1. Sorted, no duplicates. Error **"Use the 24-hour format, e.g. 18:00."** |
| Matches per day | number 1–12 | default = number of times. Hint **"Up to the number of start times."** More than the times: warning **"Some matches will share a start time."** (the engine reuses slots) |
| Leave dates empty (TBD) | toggle | skips `scheduleMatches`. All dates/times stay `null` |

Right side: a **month calendar** from the engine's output. Play days have a gold outline, days with matches are filled with `18:00 QF1` lines, and a ‹ › month switcher appears when the schedule spans several months. Below it:
* Summary note: **"8 matches on 4 days · Fri 4 Dec → Fri 11 Dec."**
* When rounds wait: **"The Final waits for the next broadcast day after the semifinals."** (shown when a dependency pushed a round to a later day).

Third place: when the third-place match and the final share a day, the wizard **swaps their times so the third-place match plays first** (§6.4).

### Step 6 · Google Sheet (optional) (`step-6.png`)

Two choice cards:
* **Later** (default): "Edit dates and scores here in the control panel. Recommended for a first setup."
* **Connect a Google Sheet**: URL field + sheet name (default `Matches`). Copy: **"Paste the link of a sheet shared as Anyone with the link → Viewer."** and **"After you press Create, download the match list (CSV) and paste it into the sheet's Matches tab. Sync starts when you turn it on in the next screen, so the new matches are never overwritten by an empty sheet."**

The connector only updates existing matches by `match_id` (docs/MATCH-SHEETS.md), so it cannot work before the matches exist. The wizard therefore saves `settings.matchSheet = { enabled: false, url, spreadsheetId, sheetName }`. The success screen offers **Download CSV** (`/api/tournaments/:id/matches.csv`) and **Turn on sync** (`PUT /api/match-sheet` on that tournament, after the user switches to it).

URL validation: must match `docs.google.com/spreadsheets/d/<id>`. Error: **"Paste the link of a Google Sheet (docs.google.com/spreadsheets/…)."**

### Step 7 · Review (`step-7.png`)

* **Summary** panel: one row per step, each with **Edit** (jumps to that step; Next returns to Review once every step is valid again).
* **What will be created** checklist, with real numbers: workspace; N teams (k without a logo yet); P players copied with their rosters; M matches with dates, best-of and bracket links; B bracket(s); design "X" applied; format graphic text.
* Note: **"The current tournament stays active. You can switch after creating."**
* **Bracket preview** from the engine, with real team names in seed slots, "Winner QF1" placeholders and `QF1 · Fri 4 Dec 18:00 · BO3` labels:
  * SE: columns per round, third place under the final;
  * DE: upper rows, then lower rows, then the grand final;
  * GSL: one mini bracket per group;
  * round robin: a round-by-round list (no tree).
* Footer: **Create tournament** (primary). While busy: **"Creating…"** (disabled). On error, an inline error box at the top of Review with the server message; the draft is kept.

### Success screen (`step-8.png`)

* **"{name} is ready"** · "8 teams, 8 matches and the bracket were created. The current tournament is still on air."
* **Switch to {name}** (primary; uses the existing switch confirmation, which mentions that live graphics are taken off air) · **Stay on {current}**.
* Next-step cards, shown only when relevant: **"5 teams have no logo"** [Open Teams] · **"Add players"** (new teams without a roster) [Open Players] · **"Check the graphics"** [Open Graphics designer] · **"Google Sheet"** [Download CSV] [Turn on sync].
* The wizard draft is cleared.

## 4. Server API

`server/formats` is not served to the browser, so previews go through the server. (When the app moves to Cloudflare, the same pure engine runs in the Worker; the endpoints stay the same.)

### 4.1 `POST /api/formats/preview` (stateless)

```jsonc
// request
{ "format": "single-elimination",
  "teams": ["k1","k2",null,"k4"],           // client keys in seed order; null = place to be decided
  "options": { "bestOf": 3, "finalBestOf": 5, "thirdPlace": true },
  "schedule": { "startDate": "2026-12-04", "weekdays": [5,6,0], "times": ["18:00","20:00"], "perDay": 2, "timezone": "Europe/Athens" } }   // or null
// response
{ "matches": [...], "brackets": [...], "warnings": [...], "counts": { "matches": 8, "days": 4, "first": "2026-12-04", "last": "2026-12-11" } }
```

* It runs `generateTournament({ format, teams, options })` with the default deterministic IDs, then (if `schedule`) `scheduleMatches(matches, brackets, schedule)` and the third-place swap (§6.4).
* Engine errors return 400 with the engine's message. The client shows it under the related field.
* The client debounces it by 250 ms and cancels stale requests (sequence number, like `designer.js refreshPreview`).
* The format cards need counts for all four formats. Send one request per enabled format (4 small calls) or add `"formats": [...]` returning a map. Either is fine.

### 4.2 `POST /api/tournaments/wizard` (atomic create)

```jsonc
{ "name": "SUPERCUP Winter 2026", "short": "SCW", "season": "Winter 2026",
  "theme": "aegean",                         // aegean | sparta
  "designPresetId": "clean",
  "timezone": "Europe/Athens",
  "teams": [
    { "key": "k1", "name": "Team Phantasma", "tag": "TP", "colors": { "primary": "#7a5cff", "secondary": "#7a5cff" },
      "copy": { "tournamentId": "tr_5bb23089", "teamId": "t_...", "players": true } },   // copy is optional
    { "key": "k4", "name": "Wolves Legion", "tag": "WLG", "colors": { ... } } ],
  "seeds": ["k1", "k4", null, "k2"],         // every team key exactly once, plus nulls for places to be decided
  "format": "single-elimination", "options": { ... },
  "schedule": { "startDate": "...", "weekdays": [5,6,0], "times": ["18:00","20:00"], "perDay": 2 } | null,
  "sheet": { "url": "https://docs.google.com/spreadsheets/d/…", "sheetName": "Matches" } | null }
// response
{ "tournament": { ...tournaments() row... }, "created": { "teams": 8, "players": 15, "matches": 8, "brackets": 1 }, "warnings": [...],
  "teamIds": { "k1": "t_ab12…", ... } }      // so the client can upload held logos
```

Server steps (validate everything **before** writing anything):
1. Validate name/short/season (same rules as `createTournament`), theme, preset, team names/tags (2.2 rules), seeds (a permutation of the keys plus nulls), sheet URL. Copy sources must exist.
2. Dry run: `generateTournament` (+ `scheduleMatches`) with temporary keys. Any engine error → 400, nothing written.
3. `createTournament({ name, short, season, broadcastDays: toBroadcastDays(weekdays), designPresetId })`, then on that record's `data`:
   * theme (§6.2);
   * teams with `newId('t')`. Copies keep `sourceTournamentId`/`sourceTeamId` (as the SUPERCUP teams do) and get their logo file duplicated to the new id (reuse what `jobs/setup-supercup-2026.mjs` / `prepare-supercup-rosters.mjs` did);
   * players copied with `newId('p')`, remapped `teamId`, `sourceTournamentId`/`sourcePlayerId`, photo files duplicated;
   * `generateTournament({ format, teams: seeds mapped to new team ids, options, newId: () => newId('m') })` → `scheduleMatches` → third-place swap → `data.matches = matches.map(m => ({ ...m, source: 'manual', extId: null, notes: '', streamWithCast: null, teamALabel: m.teamALabel ?? '', teamBLabel: m.teamBLabel ?? '' }))` (the shape of existing matches);
   * `data.settings.brackets = brackets` (each with `title`, `subtitle`, `footer` from §6.5);
   * `data.settings.tournamentFormat` (§6.5);
   * `data.settings.enabledScenes` = the current tournament's list, or all scenes;
   * `data.settings.matchSheet = { enabled: false, url, spreadsheetId, sheetName }` when `sheet` is given;
   * `data.settings.wizard = { version: 1, input: <request body without team logos>, createdAt }`.
4. `syncBracket(data)`, then `saveNow()` once. **Do not** activate the tournament.

### 4.3 Uploads to a tournament that is not active

The existing upload endpoints work on the **active** tournament only. Add tournament-scoped variants for the success screen:
* `POST /api/tournaments/:id/teams/:teamId/logo` (multipart `file`; same processing as the team logo upload);
* `POST /api/tournaments/:id/brand/league-logo`.

After Create, the client uploads the logos it held (step 1 logo, step 2 row logos) with `teamIds`. It shows one progress line, **"Uploading 3 logos…"**, and failures go into the next-step cards (**"2 logos could not be uploaded. Add them in Teams."**).

### 4.4 Edit and delete after creation

Tournaments drawer card, new actions:
* **Edit**: unchanged (name, short, season, days).
* **Regenerate bracket…**: shown when `settings.wizard` exists. Enabled only while no generated match has started (no scores, status `scheduled`). Otherwise the disabled tooltip reads **"Matches have started. Change single matches in Matches."** It reopens the wizard prefilled at **Format** (teams/seeding/schedule editable; steps 1–2 locked to the existing teams; new teams are added in Teams first). Create becomes **Replace bracket**, with the confirmation **"Replace the 8 generated matches and the bracket? Teams and players stay."** Server: `PUT /api/tournaments/:id/wizard` removes the matches whose ids are in the old `settings.brackets` rounds and creates the new ones (same steps as 4.2 §3, without teams).
* **Delete tournament…** (new; there is no delete today): type-the-name confirmation **"Type SUPERCUP Winter 2026 to delete it. Its teams, players, matches and graphics settings are removed. A backup is saved first."** Disabled for the active tournament (**"Switch to another tournament first."**) and when it is the only tournament. Server: `DELETE /api/tournaments/:id` with `{ confirm: name }` → backup to `data/backups/` → remove. Output folders are not deleted.

## 6. Implementation details coders must not miss

### 6.1 Seeds and IDs
`generateTournament` takes **team IDs in seed order** (`null` = place to be decided, which is not a bye). The wizard uses client keys for previews and the server maps them to new `t_…` ids at create. Pass `newId: () => newId('m')` so match ids match the app's format. Bracket ids from the engine (`single-elimination`, `double-elimination`, `gsl-a`, `round-robin`) are unique within one tournament, which is all `settings.brackets` needs.

### 6.2 Theme presets
`createTournament` always sets the Aegean theme today. The wizard sends `theme`:
* aegean `{ preset:'aegean', primary:'#0a1828', accent:'#d6a44c', accent2:'#8bbaec', text:'#ffffff', bgImage:null }`
* sparta `{ preset:'sparta', primary:'#141414', accent:'#c8102e', accent2:'#f2c230', text:'#ffffff', bgImage:null }`

### 6.3 Weekdays (W8)
```js
const toEngineWeekdays = broadcastDays => broadcastDays.map(d => d % 7);        // 1..7 (Mon..Sun) → 1..6, 0
const toBroadcastDays = weekdays => weekdays.map(d => d === 0 ? 7 : d).sort();   // 0..6 (Sun..Sat) → 1..7
```
The UI chips are Mon…Sun and always hold `broadcastDays` (1..7). Convert only when calling the engine.

### 6.4 Third place before the final
The engine defines the third-place round after the final, so on the same day 3P gets the later slot. After `scheduleMatches`, when `3P` and `F` share a date, swap their `time`s. Do this in a shared helper used by both preview and create, so the preview never differs from what is created.

### 6.5 Text for the bracket and format screens
* Bracket: `title` = format label (or `Group A` for GSL), `subtitle` = `"{n} teams · {Best of summary}"`, `footer` = `"{SHORT} · EVERY SERIES COUNTS"`.
* `settings.tournamentFormat` (feeds the Format scene): `subtitle` = `"{Format label} · {n} teams"`, plus one stage per phase:
  * SE: one stage per round name; headline = teams left (`8 → 4`); lines = `"Best of 3"`, `"Winners advance"`.
  * DE: Upper bracket / Lower bracket / Grand final.
  * GSL: one stage per group (headline `4 TEAMS`, lines `Two wins qualify`, `Two losses eliminate`) + `Qualified`.
  * RR: one stage `League` (headline `{n} TEAMS`, lines `Everyone plays everyone`, `3 points per win` when standings use the defaults).

  `footer` = `"{SHORT} · {FORMAT LABEL}"`. These are plain starting texts; the user edits them like today.

### 6.6 Renderer gaps (create works, but these graphics need follow-up work)
* `native-bracket.js` labels the qualification column with the fixed text **"Advance to Top 4 · GSL"**. It must use the qualification `name`s (GSL groups give "1st place"/"2nd place").
* **Double elimination** rounds carry `side: 'upper'|'lower'|'final'`. The native renderer draws all rounds as one row of columns. It needs an upper row, a lower row and the final at the right.
* **Round robin** has no tree. The bracket scene should show a **standings table** from `standings(matches, teamIds)` (new small scene or a mode of the bracket scene). Until then, the Review step says: **"Round robin shows its table on graphics after a standings screen is added; matches and schedule work now."**
* **GSL groups from the engine** have no `entrySources`, `championMatchId` or `grandFinal` node. Check that `gsl-bracket.js` renders a group with openingA/openingB/winners/losers/decider and qualifications only.
* **GF2 (reset)** is marked `optional: true`. Schedules and graphics should label it **"GF2 · only if needed"**.

### 6.7 Draft schema
`localStorage['hll-tournament-wizard-draft-v1'] = { step, name, short, season, theme, designPresetId, logo: null /* files are not persisted; re-pick */, teams: [{ key, name, tag, colors, copy, tbd }], seeds, format, options, schedule, tbdDates, sheet, savedAt }`. A draft that fails to parse is ignored. Logo files cannot be stored; after a reload the rows show "logo not kept, pick it again".

## 7. Acceptance criteria

1. Tournaments drawer → **Create tournament** opens `#/new-tournament` at step 1. The current tournament and the live output are unchanged at every step until Create.
2. Step 1 with an empty name + Next → error under the name, focus there, still step 1.
